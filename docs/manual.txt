 1. Project overview and architecture
 GrooveForge Records manufactures vinyl releases for independent artists and labels. The application stores equipment
 details, maintenance history, material receipts, artists, releases, master discs, production batches, material usage, quality
 inspections, serialized finished records, customer orders, locations and staff.

   Layer                                  Responsibility

   Swing screens                          Oracle sign-in, entity selector, editable forms, result tables and reports.

   JDBC application code                  Validate input, bind values, execute SQL, commit success and roll back failures.

   Oracle project schema                  Persist rows and enforce primary keys, foreign keys, unique values and checks.

 Student / operator
         |

         | PreparedStatement + ResultSet

 Learning outcomes
 Translate a case study into a relational model; read Chen-style ER symbols; implement DDL and DML; understand cyclic
 references and composite foreign keys; use JDBC safely; explain transaction boundaries; verify positive and negative
 cases.

 Application access
 The login screen authenticates the Oracle schema account through JDBC. It does not add a separate LOGIN business
 table. Every connected project-schema user has the privileges granted to that schema. EMPLOYEE.role is descriptive
 and is not an authorization control.

 Nullability beyond the explicitly optional selected master, validation ranges, uniqueness and date-order checks are
 implementation choices; the source does not specify a complete constraint policy.

 All other source attributes remain present. The count is 101 across the 14 business entities. Constraints and lookup
 indexes add rules, not extra business attributes.

   Design choice                               How it is handled

   Release/master circular link                Insert release with no selected master, insert its master disc, then update the release. A composite FK
                                               guarantees that the selected master belongs to that release.

   Finished record release_id                  Retained as supplied. A composite FK requires (batch_id, release_id) to match the production batch.

   Usage unit                                  Retained as supplied and checked against the material unit using a composite FK.

   Employee and warehouse references           Names and locations remain text. Their standalone registers are not silently connected through
                                               invented FKs.

   Quality defects                             One classification per visual/audio category. Additional observations go in notes. Multiple structured
                                               defects would require a schema extension.

   Order scope                                 One release per order; no order-item, record-allocation or payment table is invented.

 1.2 Business rules and normalization
 Enforced by Oracle
 Every row has a positive numeric primary key. Required attributes are NOT NULL. Child links require existing parents.
 Serial numbers and warehouse shelf/row/section combinations are unique. Enumerated statuses and categories use
 CHECK constraints. Quantities and dates satisfy the rules shown in the DDL.

 A completed batch requires both start and completion timestamps. Completion cannot precede start. Shipped or
 delivered orders require a shipped date and tracking number. Warehouse occupancy cannot exceed the entered
 capacity.

 Recorded manually; not automatically enforced across events
 Maintenance logs do not update machine status or last-maintenance date. Restocks and usage do not adjust stock. A
 quality pass does not release a batch. Orders do not change production status. No rule automatically prevents recording
 a batch against a non-operational machine; operators must review the machine register. Sampling against batch size is
 reviewed by the operator. These are deliberate tracking-scope limits.

 Normalization assessment
 The design uses one value per attribute and one row per event, supporting 1NF. The business tables use single-column
 primary keys, with no partial key dependencies under the stated assumptions. It is not accurate to claim every supplied
 relation is fully in 3NF: BATCH_MATERIAL_USAGE repeats unit determined by material_id, and FINISHED_RECORD
 repeats release_id determined by batch_id. Those source-required redundancies are retained and protected with
 composite foreign keys.

 supplier_name in RAW_MATERIAL is the current/default supplier label; supplier_name in RESTOCK_LOG is the
 historical supplier for that receipt. They may legitimately differ. Staff names are historical text labels rather than stable
 employee references.

 Possible future redesign, outside this delivery
 If authorized later, replace text staff/location references with IDs, remove derived duplicate release/unit fields, introduce
 structured defect details, and implement audited workflow transitions. Those changes would alter the supplied model.

 Expected: USER is GROOVEFORGE; 14 tables and 14 sequences are created; seed rows are inserted and committed.
 build_output.txt captures the run. build.sql stops on SQL errors instead of silently continuing.

 3. Run the acceptance checks while sample data is unchanged, then examine reports.

 @05_acceptance_tests.sql
 @03_reports.sql
 @06_transaction_demo.sql

 Expected: ALL 14 ACCEPTANCE CHECKS PASSED. The transaction demo shows Quality Hold temporarily, then
 restores Completed / Ready to Ship using ROLLBACK.

 Build order and restart behavior
 Parent tables precede children. The optional selected-master constraint is added after both release and master tables
 exist. The seed inserts releases with NULL selected masters, creates master rows, then assigns selected masters. DDL
 commits in Oracle, so a failed build can leave partial objects. Use a fresh project schema for a clean retry; no destructive
 reset is included.

 CREATE TABLE VINYL_RELEASE (
    release_id NUMBER(9) NOT NULL,
    artist_id NUMBER(9) NOT NULL,

    format VARCHAR2(10) NOT NULL,

    CHECK (estimated_runtime_minutes > 0),

 );

 4.3 JDBC implementation and transaction boundary
 Each module reuses the same tested form engine. Table and column identifiers come from Model.java, never from a text
 box. Values are bound using PreparedStatement. Date and number parsing occurs before JDBC writes.

 (machine_name, model_number, installed_date,
  last_maintenance_date, status, machine_id)
 VALUES (?, ?, ?, ?, ?, ?);

 SET machine_name = ?, model_number = ?, installed_date = ?,
     last_maintenance_date = ?, status = ?
 WHERE machine_id = ?;

 connection.setAutoCommit(false);
 try {
     // Bind user values with setString / setBigDecimal / setDate.
     // Execute exactly one insert, update or delete.
     connection.commit();
 } catch (Exception ex) {
     connection.rollback();
     throw ex;
 }

 The example is explanatory; App.java contains complete executable methods. A SwingWorker performs database work
 off the event-dispatch thread. Controls are temporarily disabled to keep the selected module and input stable during the
 operation. The result table refreshes only after a successful commit.

 A selected row cannot accidentally be added as a duplicate: the user must Clear before Add. Updates require a selected
 or searched ID. Failed writes retain the form for correction. All resources use try-with-resources where appropriate.

 Deletion and circular links
 To delete a selected master disc, first clear its selection from VINYL_RELEASE, then remove the disc if no other
 references exist. To remove a release, remove or reassign its batches, orders, finished records and masters in
 dependency order. Do not disable constraints to make deletion succeed.

 7. Viva questions with model answers
 Why use a separate schema?
 It separates project objects and privileges from administrator/system objects.

 Why use sequences?
 They generate concurrent-safe numeric identifiers without requiring modern identity columns. Gaps are normal.

 Why is the master link nullable?
 It breaks the insertion cycle: create release, create its master, then select the master.

 Why use a composite master FK?
 A simple disc FK proves existence only. The pair also proves the disc belongs to the same release.

 Why retain release_id on finished records?
 The supplied model requires it. A composite batch/release FK prevents contradictory values.

 Is the schema fully normalized to 3NF?
 No blanket claim is made. Repeated unit and release fields are controlled source-required redundancies.

 Why does stock not change on receipt?
 The case study specifies tracking without calculations; stock and event quantities are manually recorded.

 What does PreparedStatement prevent?
 Bound values are treated as data, reducing SQL-injection risk. Identifiers come from a fixed allowlist.

 7.1 Viva questions - application and testing
 Why commit?
 It makes successful changes durable and visible to other sessions.

 Why roll back?
 It removes uncommitted changes after a failed operation or canceled demonstration.

 What does a foreign-key delete error mean?
 A child still references the parent. Rejecting the delete preserves integrity.

 Why are employees/locations standalone?
 The case study supplies text names/locations but no foreign-key attributes connecting those registers.

 What does the employee Admin role grant?
 Nothing automatically. It is a descriptive field; database authentication controls this client.

 What is a ResultSet?
 The cursor-like JDBC result of a query, read to populate the Swing table.

 Why SwingWorker?
 It performs JDBC work in the background so the UI event thread stays responsive.

 What remains to validate on Oracle?
 Database-specific DDL/PLSQL behavior, JDBC compatibility, actual authentication and end-to-end lab CRUD.
